# P-002 — LED Indicator

**Course:** Electronics & Programming — Level 1  
**Session:** 02 — LEDs & Polarity

> **Status:** Production draft derived from the established ITS Education project sequence and course framework. Exact component part numbers and lesson-specific numerical values must be validated before classroom use.

## Purpose
Use LED orientation deliberately to create a working indicator.

## Learning objectives
- Explain the main concept in simple technical language.
- Assemble the intended system.
- Test deliberately rather than only copy a demonstration.
- Identify and correct basic faults.
- Explain what was built and what was changed.

## Required concepts
Anode/cathode; polarity; forward direction; visual indication.

## Components and materials
LEDs; resistors; breadboard; jumper wires; low-voltage supply.

Exact ratings, quantities, brands, and substitutions belong in the laboratory BOM.

## Tools
- Breadboard and jumper wires
- Appropriate laboratory hand tools
- Multimeter where useful

## Safety
Power must remain within the laboratory low-voltage system.

## System architecture
Source/power → circuit or control element → output → return path.

The student should draw the actual circuit in the engineering notebook.

## Build procedure
1. Review the goal and identify components.
2. Inspect components and orientation.
3. Build according to the lesson guidance.
4. Check connections before power.
5. Test one function at a time.
6. Record observations.
7. Debug using the ITS cycle.

**Project-specific focus:** Identify LED terminals; build indicator; reverse orientation as an observation; restore correct polarity.

## Testing
Record expected behavior, actual behavior, changes between tests, and repeatability.

## Debugging
**Observe → Describe → Hypothesize → Test → Identify → Correct → Test again**

Change one relevant variable at a time when practical.

## Improvement
After the basic system works, make one controlled improvement without losing the original function.

## Student explanation
The student should explain the purpose, inputs, outputs, important components, one fault, the debugging process, and one possible improvement.

## Teacher guide
Ask questions before giving solutions. Require observation and testing. Differentiate support/core/extension. Collect evidence of student thinking.

## Assessment
Use the Level 1 competency framework, especially Electronics, Engineering, Debugging, and Communication.

## Required evidence
- Circuit/system sketch
- Build evidence
- Test observations
- Debugging note
- Final explanation
- Improvement/reflection

## Success criteria
Student identifies polarity and produces a repeatable indicator.

## Quality check
- [ ] System demonstrates the intended behavior.
- [ ] Student can explain the concept.
- [ ] Student performed a meaningful test.
- [ ] Student can describe a debugging step.
- [ ] Evidence is recorded in the engineering notebook.
- [ ] Safety requirements were followed.
