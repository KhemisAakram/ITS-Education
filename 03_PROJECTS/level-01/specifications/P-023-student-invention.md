# P-023 — Student Invention

**Course:** Electronics & Programming — Level 1  
**Session:** 23 — Final Engineering Project

> **Status:** Production draft derived from the established ITS Education project sequence and course framework. Exact component models, mechanical dimensions, power arrangements, pin assignments, and final assessment thresholds must be validated before classroom use.

## Purpose
Design and build a student-selected technology project using course concepts.

## Learning objectives
- Apply previously learned concepts in an integrated system.
- Plan before building.
- Test deliberately and record evidence.
- Debug hardware, software, mechanical, or system-level faults as appropriate.
- Communicate design decisions and improvements.

## Required concepts
Problem definition; design; integration; iteration; communication.

## Components and materials
Student-selected components from approved Level 1 inventory; tools; workbook/documentation.

Exact quantities, ratings, brands, substitutions, and approved alternatives belong in the laboratory BOM.

## Tools
- Engineering notebook/workbook
- Standard Level 1 laboratory tools
- Computer/programming equipment where required
- Multimeter and other shared instruments where appropriate

## Safety
Teacher approves design, power, tools, and moving mechanisms before build.

Teacher approval is required before energizing a new configuration or operating a moving mechanism.

## System architecture
Students should document the actual system as blocks and then as a detailed circuit/mechanical/program design.

## Build procedure
1. Define the intended behavior.
2. Sketch the system.
3. Identify components and risks.
4. Build one subsystem at a time.
5. Test each subsystem.
6. Integrate.
7. Debug.
8. Improve.
9. Prepare the explanation.

**Project-specific focus:** Define problem; sketch system; select components; build; test; debug; improve; prepare explanation.

## Testing
Define expected behavior before testing. Record observations, faults, changes, and final results.

## Debugging
Use:
**Observe → Describe → Hypothesize → Test → Identify → Correct → Test again**

Students should identify whether a fault is mechanical, electrical, software, configuration, or integration-related.

## Improvement
At least one documented improvement should be made after the first working version or first usable demonstration.

## Student explanation
The student should explain the problem, design, system architecture, important components, testing, failure/debugging, and improvement.

## Teacher guide
The teacher acts as facilitator and debugging coach. For open projects, evaluate the quality of the engineering process as well as the final result.

## Assessment
Use the Level 1 competency framework. Relevant domains include Electronics, Programming, Actuators, Robotics, Engineering, Debugging, and Communication.

## Required evidence
- Problem/goal statement
- System sketch
- Build evidence
- Test evidence
- Debugging record
- Improvement record
- Final explanation
- Engineering notebook/portfolio evidence

## Success criteria
Student produces a working prototype or documented partial prototype and explains decisions and debugging.

## Quality check
- [ ] Student defined the goal.
- [ ] Student planned before building.
- [ ] System was tested.
- [ ] At least one fault or design limitation was addressed.
- [ ] Student documented an improvement.
- [ ] Student can explain the system.
- [ ] Safety requirements were followed.
