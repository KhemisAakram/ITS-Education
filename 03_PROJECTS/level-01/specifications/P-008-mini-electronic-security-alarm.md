# P-008 — Mini Electronic Security Alarm

**Course:** Electronics & Programming — Level 1  
**Session:** 08 — Electronic Alarm

> **Status:** Production draft derived from the established ITS Education project sequence and course framework. Exact sensor models, ratings, quantities, and lesson-specific numerical values must be validated before classroom use.

## Purpose
Combine an input with a sound output to create a simple alarm.

## Learning objectives
- Explain the main concept.
- Assemble or configure the intended system.
- Test the input and observe its effect.
- Debug basic faults.
- Explain the relationship between input and output.

## Required concepts
Trigger condition; input/output; system response.

## Components and materials
Buzzer; button/switch or planned trigger; LED; resistors; breadboard; supply.

## Tools
- Breadboard and jumper wires
- Appropriate laboratory tools
- Multimeter where useful
- Controller/programming equipment where specified by the lesson

## Safety
No mains voltage or hazardous alarm mechanisms.

## System architecture
**Physical condition/input → sensor → processing/control where applicable → output**

Students should document the actual architecture in their engineering notebook.

## Build procedure
1. Identify the sensor and expected response.
2. Inspect connections.
3. Build the circuit/system.
4. Test the sensor under controlled conditions.
5. Record observations.
6. Modify one relevant variable at a time.
7. Debug and retest.

**Project-specific focus:** Build alarm; define trigger state; test normal/alarm states; improve reliability.

## Testing
Test at least two meaningfully different input conditions. Record expected behavior, observed behavior, and repeatability.

## Debugging
**Observe → Describe → Hypothesize → Test → Identify → Correct → Test again**

## Improvement
Change one aspect of the system to make the response clearer, more reliable, or better documented.

## Extension
Where appropriate, add another output, another condition, or a more independent control rule using approved Level 1 equipment.

## Student explanation
The student should explain what the sensor detects, what the system does with that information, and how the output changes.

## Teacher guide
Emphasize observation before explanation. Ask students to predict what will happen, then test the prediction.

## Assessment
Assess Sensors, Electronics, Engineering, Debugging, and Communication as applicable.

## Required evidence
- Sensor/system sketch
- Observation table
- Test result
- Debugging note
- Final explanation
- Improvement/reflection

## Success criteria
Student demonstrates both states and explains what triggers the alarm.

## Quality check
- [ ] Sensor responds to a deliberate test.
- [ ] Student can explain the input/output relationship.
- [ ] Student performed controlled testing.
- [ ] Student documented a debugging or improvement step.
- [ ] Safety requirements were followed.
