# Educational Philosophy

## Core philosophy
Project-driven, hands-on learning. Concepts are introduced because students need them to solve a problem or build something.

## Learning cycle
**Learn → Experiment → Build → Break → Debug → Understand → Improve → Create**

## Teaching model
- 20% theory
- 30% guided experimentation
- 50% project work

Example 90-minute session:
10 min concept, 15 min demonstration, 20 min guided experiment, 35 min project, 10 min presentation/debugging.

## Debugging
**Problem → Observation → Hypothesis → Test → Correction → Retest**

Teachers should avoid immediately fixing every problem.

## Progressive difficulty
**Simple circuits → Electronics → Microcontrollers → Robotics → Embedded systems → Engineering projects**

## Understanding
Students should explain what they built, why it works, why it failed, what components do, how software controls hardware, and what they would change.

## Independence
**Follow instructions → Modify instructions → Solve a defined problem → Design a solution → Define and build an original project**

## Real projects
Early: **LED → Button → Sensor → Motor**  
Intermediate: **Arduino → Robot → IoT → Automation**  
Advanced: **PCB → Embedded system → Robotics → Product**

## Teacher role
Explain, demonstrate, question, challenge, maintain safety, coach debugging, encourage experimentation, monitor progression, and give feedback.

## Final principle
Move students from **"Tell me how to build it."** to **"I have an idea. Let me figure out how to build it."**
